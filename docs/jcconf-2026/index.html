From prompting to specification

Functional specification

Define what the system must do and why

  • Business rules and outcomes
  • User stories and acceptance criteria
  • Constraints and quality attributes
  • No implementation decisions yet

A business contract shared through tools such as Jira, GitHub, or Azure DevOps.

From prompting to specification

Technical specification

Define how the system will satisfy the contract

  • Components, interfaces, and data model
  • Dependencies and architectural decisions
  • Migration and compatibility strategy
  • Testing and validation strategy

OpenSpec makes these decisions explicit.

From prompting to specification

Engineer the workflow around the agent


Intent → Decisions → Constraints → Context → Agent → Evidence

Constrain the problem before accelerating the solution.

Takeaways

  1. Formalize cross-team communication to avoid "Frankenstein" systems.
  2. Architects must strengthen consistency across domains, subdomains, and teams.
  3. An AI-agent harness is not a silver bullet.
  4. Specify before generating.
  5. Engineer the workflow, not just the prompt.
  6. Optimize for system awareness and system correctness.
  7. Every organization requires an AI Registry.
